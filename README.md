# Prodaco Services website

Static marketing site for Prodaco Services (Kenyan animal nutrition & dairy
farm services) with a tiny zero-dependency Node backend for the contact form.

## What's here

```
website/
├── public/            # what the browser sees
│   ├── index.html         Home
│   ├── training.html      Training options
│   ├── consultancy.html   Farm benchmarking & organisation
│   ├── nutrition.html     Silage, hay, dairymeal
│   ├── comfort.html       Cow shade design
│   ├── activities.html    On-farm services
│   ├── about.html         About the company
│   ├── contact.html       Contact form (POSTs to /api/contact)
│   ├── 404.html           Branded not-found page
│   ├── styles.css         Shared stylesheet
│   ├── site.js            Nav toggle + contact-form fetch handler
│   ├── favicon.svg
│   ├── sitemap.xml
│   └── robots.txt
├── server.js          Node HTTP server (static files + /api/contact)
├── db.js              SQLite (leads table) via node:sqlite
├── lib.js             sendMail() via Resend HTTPS API
├── package.json
├── railway.json       start command
├── scripts/rebuild.mjs  regenerate /public from source pages (idempotent)
├── .env.example
└── .gitignore
```

## Local dev

```
node --version         # must be 22.5+ for node:sqlite
cp .env.example .env   # set RESEND_API_KEY + MAIL_FROM if you want to test email
npm start              # or npm run dev for watch mode
```

Open http://localhost:3000

## Contact form pipeline

Browser form → `POST /api/contact` (JSON) → validate → save to SQLite `leads`
table → email `info@prodacoservices.com` via Resend → JSON `{ok:true}` back to
the page → success message shown inline.

Guards:
- Honeypot field (`name="website"`, hidden) — bots that fill it get a silent 200.
- Per-IP rate limit (5 posts / 10 min).
- 10 KB request cap.
- All errors return 400 with a friendly message (never 5xx — Cloudflare would
  mask the real message).

## Deploy — Railway

1. Push this folder to a GitHub repo.
2. Railway → **New Project → Deploy from GitHub** → pick the repo.
3. Add a **Volume** at mount path `/data` (Service → Settings → Volumes).
4. Set env vars under **Variables**:
   - `DB_PATH=/data/prodaco.db`
   - `RESEND_API_KEY=re_...`
   - `MAIL_FROM=info@prodacoservices.com`
   - `INFO_INBOX=info@prodacoservices.com`
5. Service → Settings → **Domains** → add `prodacoservices.com` (and `www`).
6. Point DNS at Railway via Cloudflare (see `docs/services/` in the patahome
   repo for the pattern — same setup here).

## Regenerating pages

The 8 HTML files in `/public` are generated by `scripts/rebuild.mjs` from the
source `.html` files at the project root (Anthony's original drafts). If you
edit content in a source file, run:

```
npm run rebuild
```

That reapplies the shared header, footer, SEO tags, favicon, and WhatsApp
floating button so everything stays consistent.

## Notes for the next dev

- `+254 235 91958` in the original files looks like a landline (`235 XXXXX`);
  the rebuilt pages sanitise it to a hyphenless form for `tel:` links but the
  displayed number should be verified with the client.
- Domain is assumed to be `prodacoservices.com`. If it changes, update:
  - `BASE_URL` in `scripts/rebuild.mjs`
  - `sitemap.xml` and `robots.txt`
  - Then `npm run rebuild`.
